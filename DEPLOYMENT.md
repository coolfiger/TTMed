# TTMed — Deployment Guide

## Server Requirements

| Component | Minimum | Recommended |
|---|---|---|
| OS | Ubuntu 22.04 LTS | Ubuntu 22.04 LTS |
| CPU | 2 cores | 4 cores |
| RAM | 4 GB | 8 GB |
| Disk | 50 GB SSD | 100 GB SSD |
| Panel | HestiaCP | HestiaCP |
| PHP | 8.3 (FPM) | 8.3 (FPM) |
| MySQL | 8.0 | 8.0 |
| Redis | 7.x | 7.x |
| Node.js | 22.x (build only) | 22.x |

No Docker. The application runs natively under HestiaCP's Nginx + PHP-FPM stack.

## HestiaCP Setup

### 1. Create the web domain

In HestiaCP, create a web domain for the application (e.g., `app.ttmed.tt`). HestiaCP will create the directory structure at `/home/{user}/web/{domain}/`.

Configure SSL via HestiaCP's Let's Encrypt integration.

### 2. Configure PHP-FPM

In HestiaCP → Web → (domain) → PHP version, select PHP 8.3.

Required PHP extensions (verify all are enabled):
```
pdo_mysql, mbstring, xml, bcmath, json, curl,
openssl, zip, gd, intl, exif, fileinfo, redis
```

Increase PHP limits for file uploads and PDF generation in the domain's PHP configuration:
```ini
upload_max_filesize = 20M
post_max_size = 25M
memory_limit = 256M
max_execution_time = 120
```

### 3. Set the document root

HestiaCP sets the document root to `/home/{user}/web/{domain}/public_html`. Laravel's public folder must be symlinked or the document root must point to `/home/{user}/web/{domain}/public_html/public`.

The simplest approach on Hestia: deploy the application to `/home/{user}/web/{domain}/laravel/` and symlink Laravel's `public/` folder contents into `public_html/`.

Alternatively, configure a custom Nginx template (see below) that sets the root to the Laravel `public` directory directly.

### 4. Custom Nginx template for Laravel

Create a custom Nginx template in HestiaCP for the domain that includes:

```nginx
root /home/{user}/web/{domain}/public_html;

index index.php;

location / {
    try_files $uri $uri/ /index.php?$query_string;
}

location ~ \.php$ {
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    include fastcgi_params;
}

location ~* /storage/tenants/ {
    deny all;
    return 403;
}
```

The `deny all` rule on `/storage/tenants/` is a defence-in-depth measure — the storage directory should already be outside the web root.

## Application Deployment

### Directory Structure on Server

```
/home/{user}/
├── web/{domain}/
│   └── public_html/        → symlinks to ttmed/public/
├── ttmed/                  ← application root (outside web root)
│   ├── app/
│   ├── config/
│   ├── database/
│   ├── public/             ← this is what Nginx should serve
│   ├── resources/
│   ├── routes/
│   ├── storage/
│   │   ├── tenants/        ← medical centre files (never web-accessible)
│   │   ├── app/
│   │   ├── framework/
│   │   └── logs/
│   ├── .env                ← permissions 600
│   └── ...
```

### Initial Deployment Steps

```bash
# 1. Clone the repository
cd /home/{user}
git clone https://github.com/coolfiger/TTMed.git ttmed
cd ttmed

# 2. Install PHP dependencies
composer install --optimize-autoloader --no-dev

# 3. Install and build frontend assets
npm install
npm run build

# 4. Configure environment
cp .env.example .env
# Edit .env with production values
php artisan key:generate

# 5. Set permissions
chmod 600 .env
chmod -R 755 storage bootstrap/cache
chown -R {user}:{user} storage bootstrap/cache

# 6. Run platform database migrations
php artisan migrate --database=platform

# 7. Seed platform (creates initial platform admin)
php artisan db:seed --class=PlatformSeeder

# 8. Create tenant file storage root
mkdir -p storage/tenants
chmod 750 storage/tenants

# 9. Link public storage (for non-sensitive public assets like logos)
php artisan storage:link

# 10. Set up queue worker (see below)
# 11. Set up Reverb WebSocket server (see below)
# 12. Configure cron job (see below)
```

### .env Configuration


## MySQL Setup

### Platform database

```sql
CREATE DATABASE ttmed_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ttmed_platform_user'@'localhost' IDENTIFIED BY 'strong_password';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, INDEX, ALTER
  ON ttmed_platform.* TO 'ttmed_platform_user'@'localhost';
FLUSH PRIVILEGES;
```

### Tenant database provisioning

Tenant databases are created programmatically by `TenantProvisioningJob`. That job uses a privileged provisioning MySQL user (credentials stored only in `.env`):

```sql
CREATE USER 'ttmed_provisioner'@'localhost' IDENTIFIED BY 'strong_password';
GRANT CREATE, DROP ON *.* TO 'ttmed_provisioner'@'localhost';
GRANT GRANT OPTION ON *.* TO 'ttmed_provisioner'@'localhost';
FLUSH PRIVILEGES;
```

Each tenant gets its own MySQL user with access only to its own database:
```sql
-- Example for tenant "medsouth"
CREATE DATABASE ttmed_medsouth CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ttmed_t_medsouth'@'localhost' IDENTIFIED BY '{generated_password}';
GRANT SELECT, INSERT, UPDATE, DELETE, INDEX, CREATE TEMPORARY TABLES
  ON ttmed_medsouth.* TO 'ttmed_t_medsouth'@'localhost';
FLUSH PRIVILEGES;
```

The tenant's MySQL user has no `CREATE`, `DROP`, `ALTER`, or `GRANT` privileges. Schema changes are applied by the provisioner during provisioning and by the deployment migration runner during upgrades.

## Queue Workers (Laravel Horizon)

Horizon manages Redis queue workers. Configure it as a Supervisor process.

Install Supervisor:
```bash
apt-get install -y supervisor
```

Create `/etc/supervisor/conf.d/ttmed-horizon.conf`:
```ini
[program:ttmed-horizon]
process_name=%(program_name)s
command=php /home/{user}/ttmed/artisan horizon
autostart=true
autorestart=true
user={user}
redirect_stderr=true
stdout_logfile=/home/{user}/ttmed/storage/logs/horizon.log
stopwaitsecs=3600
```

```bash
supervisorctl reread
supervisorctl update
supervisorctl start ttmed-horizon
```

## WebSocket Server (Laravel Reverb)

Reverb runs as a PHP WebSocket server. Add to Supervisor:

Create `/etc/supervisor/conf.d/ttmed-reverb.conf`:
```ini
[program:ttmed-reverb]
process_name=%(program_name)s
command=php /home/{user}/ttmed/artisan reverb:start --host=127.0.0.1 --port=8080
autostart=true
autorestart=true
user={user}
redirect_stderr=true
stdout_logfile=/home/{user}/ttmed/storage/logs/reverb.log
```

Configure Nginx to proxy WebSocket connections:
```nginx
location /app/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
    proxy_set_header Host $host;
}
```

## Scheduled Tasks (Cron)

Add to the system cron for the application user:

```bash
crontab -e
```

```
* * * * * cd /home/{user}/ttmed && php artisan schedule:run >> /dev/null 2>&1
```

Scheduled tasks include:
- Appointment reminder emails (daily, 24h before)
- Subscription expiry checks (daily)
- Database backup (daily at 2:00 AM)
- Document backup (daily at 3:00 AM)
- Follow-up reminder generation (daily)
- Session cleanup (hourly)
- Expired stock alerts (daily)

## Deployment Updates

```bash
cd /home/{user}/ttmed

# Pull latest code
git pull origin main

# Install/update dependencies
composer install --optimize-autoloader --no-dev
npm install
npm run build

# Clear and rebuild caches
php artisan config:clear
php artisan route:clear
php artisan view:clear
php artisan config:cache
php artisan route:cache

# Run any new migrations
# IMPORTANT: tenant migrations require a separate artisan command
php artisan migrate --database=platform
php artisan tenants:migrate

# Restart queue workers
php artisan horizon:terminate
supervisorctl restart ttmed-horizon

# Restart Reverb
supervisorctl restart ttmed-reverb
```

The `tenants:migrate` command is a custom artisan command (implemented in Phase 1) that iterates all active tenants in the platform DB and runs pending migrations against each tenant database.

## Backups

See BACKUP.md for full procedures. Summary:

- **Platform DB**: Daily mysqldump, encrypted, stored locally + off-server
- **Tenant DBs**: Daily mysqldump per tenant, encrypted, stored in `storage/tenants/{uuid}/backups/`
- **Tenant files**: Daily rsync to off-server location
- **Retention**: 30 days rolling

Restoration of a single tenant does not require downtime for other tenants.

## Monitoring

- Laravel Horizon dashboard at `/horizon` (platform admin access only, rate-limited)
- Application logs: `storage/logs/laravel.log`
- Horizon logs: `storage/logs/horizon.log`
- Reverb logs: `storage/logs/reverb.log`
- Failed jobs visible in Horizon; alerts configured for persistent failures
- HestiaCP provides basic server metrics

Consider adding UptimeRobot or similar external uptime monitoring on the application URL.
